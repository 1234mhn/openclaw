# 💥 知识卡片碰撞引擎

> **核心理念：** 知识不是孤岛。把不同领域的卡片扔到一起，碰撞出来的东西才是真正的新知。

## 工作流程

### 1. 碰撞模式（三种指令）

#### ⚡ 随机碰撞 `/撞卡`

从知识库中随机选取 **2-3张不同领域** 的卡片，强制连接，输出新洞察。

#### 🎯 定向碰撞 `/碰撞 [卡A] x [卡B]`

用户指定两张卡，强制它们撞。

```
用户：碰撞 个人IPO x 焦虑的本质
系统分析：
  KC-BOOK-002 个人IPO → 把自己当产品
  KC-BOOK-007 焦虑的本质 → 大脑警报系统
碰撞结果：
  把自己当产品 → 焦虑的本质是产品有缺陷未解决
  → 新方法：「焦虑清单=产品缺陷清单」
  → 行动：列出你焦虑的事，就是你的产品待优化列表
```

#### 🔗 辐射碰撞 `/辐射 [卡ID]`

围绕一张核心卡，找出所有能连上的其他卡。

```
用户：辐射 KC-BOOK-009
系统分析：
  核心：KC-BOOK-009 核心能力不可培训
  相关卡：
    KC-BOOK-002 个人IPO → 核心能力=护城河
    KC-BOOK-003 卡片四铁律 → 锻造=自主学习
    KC-BOOK-005 变现三问 → 变现需要核心能力
    KC-BOOK-006 个人系统六层架构 → 基础层=自学
  碰撞成果：「核心能力」的知识图谱
```

### 2. 碰撞产出格式

每次碰撞输出一张 **碰撞记录卡**：

```
💥 碰撞记录
━━━━━━━━━━━━━━━━━
🪨 卡A：[卡ID] [卡片名]
🪨 卡B：[卡ID] [卡片名]
━━━━━━━━━━━━━━━━━
💡 碰撞后发现

[新的洞察/连接/方法]

📐 新行动指南

[从碰撞中产出的可操作方法]

🔗 新连接

· 用[卡A的X]来解决[卡B的Y]
· [卡B的X]视角拓展了[卡A的Y]
· 组合成新方法论：[命名]
━━━━━━━━━━━━━━━━━
📅 碰撞日期：YYYY-MM-DD
```

### 3. 碰撞池来源

三大池子，只限这里面的内容碰撞：

| 池子 | 路径 | 缩写 |
|:----|:-----|:----:|
| 📚 **读书笔记** | 知识库/读书笔记/（KC-BOOK卡片） | BOOK |
| 💡 **洞见** | 灵感/想法碎片 | INSIGHT |
| 🔄 **复利库知识卡片** | 知识库/基础知识/等 | COMPOUND |

### 4. 🔔 自动碰撞模式（核心）

系统在后台自动运行，无需用户命令：

**触发条件：**
- 每次新增/更新读书笔记卡片 → 自动跟其他所有卡片做一次碰撞扫描
- 每次新增/更新洞见/灵感 → 自动跟现有卡片做一次碰撞扫描
- 每周日自动做一次全库批量碰撞

**碰撞逻辑：**
1. 新内容入库后 → 自动扫描三大池子中所有卡片
2. 找出「以前没连过」或者「之前连得弱」的连接
3. 如果碰撞产出有新意 → 主动推送给用户（不用等问）
4. 如果碰撞产出一般 → 记录但不打扰用户

**推送格式：**
```
🔔 碰撞发现

今天[新卡片名]入库后，自动跟以下卡片产生了新连接：

🪨 [已有卡A] + 🪨 [新卡/洞见]
→ [新洞察一句话]

🪨 [已有卡B] + 🪨 [新卡/洞见]
→ [新洞察一句话]

💡 我觉得这个你可能没注意到...
[扩展说明]
━━━━━━━━━━━━━━━━━
📅 自动扫描时间：YYYY-MM-DD HH:mm
```

### 5. 碰撞深加工

- 碰撞产出够好 → 锻造成KC新卡
- 更新参与卡的「关联卡片」字段
- 在卡片上标记已碰撞次数

## 命令速查

| 命令 | 用途 | 示例 |
|:----|:----|:----|
| `/撞卡` | 随机抽2-3张卡碰撞 | "撞一下" |
| `/碰撞 [A] x [B]` | 指定两张卡碰撞 | "碰撞 个人IPO x 焦虑的本质" |
| `/辐射 [卡ID]` | 围绕一张卡找所有连接 | "辐射 KC-BOOK-009" |
| `/碰撞池` | 查看当前可撞的卡片清单 | "看看能撞什么" |

## 预置碰撞题目

1. **核心能力 x 个人系统** — 如何用自主学习能力构建六层系统？
2. **焦虑本质 x 需求自检** — 焦虑是否能帮我们发现真实需求？
3. **变现三问 x 纳瓦尔之盾** — 你的护城河够不够变现？
4. **卡片四铁律 x 个人IPO** — 锻造卡片本身就是打造个人产品？
5. **记忆三步骤 x 卡片锻造** — 编码→存储→提取与卡片锻造系统的映射
